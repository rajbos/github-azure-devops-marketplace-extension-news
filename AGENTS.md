# Agent instructions

## Project

This .NET 8 solution monitors Azure DevOps extensions and GitHub Marketplace actions, stores results as JSON in Azure Blob storage, and publishes GitHub Actions news to the [news site](https://devops-actions.github.io/github-actions-marketplace-news) and its RSS feed. Twitter posting is disabled. Organization action scanning also discovers actions outside the marketplace.

The solution is `AzDoExtensionNews\AzDoExtensionNews.sln`:

- `AzDoExtensionNews`: Azure DevOps extension news console application.
- `GitHubActionsNews`: GitHub Actions marketplace news console application.
- `News.Library`: shared functionality; put reusable behavior here.
- `AzDoExtensionNews.UnitTests`: NUnit tests.
- `GitHubActionsNews.Tests`: MSTest tests, including Playwright browser tests.

Configuration uses JSON and environment variables. Keep credentials in secret management, never in source or logs. `*.secrets.json` files are gitignored. The existing blob library, `Microsoft.Azure.Storage.Blob`, is legacy; prefer `Azure.Storage.Blobs` for new development where appropriate.

## Local build and tests

Run these commands from the repository root. Prerequisites are the .NET 8 SDK, PowerShell (`pwsh`), Git, and NuGet access for any uncached packages. Restore in locked mode; building and testing can write local build and test outputs but do not run the publishing workflow.

```powershell
dotnet restore .\AzDoExtensionNews\AzDoExtensionNews.sln --locked-mode
dotnet build .\AzDoExtensionNews\AzDoExtensionNews.sln -c Release --no-restore
```

For browser tests, install the Playwright Chromium version generated by the build. The host also needs Playwright's OS dependencies; CI uses the matching Playwright .NET container (`mcr.microsoft.com/playwright/dotnet:v1.61.0-noble`), which includes the browser and dependencies. Installing browsers requires network access.

```powershell
pwsh .\AzDoExtensionNews\GitHubActionsNews.Tests\bin\Release\net8.0\playwright.ps1 install chromium
```

The CI test selection excludes the `MarketplaceScraping` category:

```powershell
dotnet test .\AzDoExtensionNews\AzDoExtensionNews.sln -c Release --no-build --no-restore --filter "TestCategory!=MarketplaceScraping"
```

This filter is **not offline**: untagged `VerifiedCreator_Tests` visit GitHub Marketplace, and `GetActionTypeAndNodeVersion_Tests` access GitHub and an invalid URL. They also launch Chromium. The `MarketplaceScraping` pagination test uses the live marketplace and can depend on its content, availability and rate limits. To include it, omit the filter:

```powershell
dotnet test .\AzDoExtensionNews\AzDoExtensionNews.sln -c Release --no-build --no-restore
```

Choose focused tests appropriate to the change; the GitHub release API client tests use a fake HTTP handler. Run relevant tests after code changes. For publishing authentication changes, the following standalone regression checks use synthetic credentials, mocked Git calls and a disposable local Git remote; they do not scrape, contact GitHub or publish news:

```powershell
pwsh -NoProfile -File .\.github\workflows\tests\publishing.Tests.ps1
```

The manually dispatched **Check repository PAT** workflow checks the stored classic PAT's authentication, repository scope and push access, and performs unchanged default-branch dry-run pushes to both repositories. It does not exercise pull-request creation; that permission is inferred from scope and access. A successful dry-run does not prove a future changed commit will pass branch protection or other server-side rules. This is a live credential/network check, not a local test; do not dispatch it without authorization.

## Side effects and credentials

Do not treat `dotnet run`, scraper commands, storage operations, scheduled deployment or the publishing script as tests. Depending on the command and configuration, they can access live marketplace/GitHub APIs, read or write Azure Blob data, create local output, or publish commits to the separate news repository. Inspect the selected command and configuration and obtain authorization before running live operations; use isolated tests instead when possible.

The news publishing workflow passes the `PAT` Actions secret as `NEWS_PUBLISH_TOKEN`; the source repository's `GITHUB_TOKEN` is for API reads, not cross-repository publishing. Preserve the existing credential-safe approach: clone without credentials, validate access before generating posts, and pass Git authentication through process-only configuration, never command arguments, remote URLs, persisted Git config or interpolated PowerShell workflow commands. Never print tokens or raw authentication output. If a token appears in logs, it must be rotated; changes to scripts do not revoke it or remove historical logs. See the README's news publishing credentials section for repository permissions and operational details.

## Conventions

- Package versions are centrally managed in `Directory.Packages.props`; `PackageReference` entries omit versions. Use locked restores. If dependencies change, review them and update affected `packages.lock.json` files with `dotnet restore .\AzDoExtensionNews\AzDoExtensionNews.sln --use-lock-file --force-evaluate`; include the lock files with the dependency change. Dependabot workflows also maintain lock files.
- Follow existing patterns, use appropriate error handling and logging, and add focused tests for changed behavior. Update the README when usage or behavior changes.
- Pin GitHub Actions to full commit SHAs; Dependabot manages and groups action updates.
- CI restores, builds, tests and publishes `AzDoNews` and `GitHubNews` build artifacts. This artifact packaging is distinct from running scrapers or publishing news. CodeQL and dependency review workflows provide additional checks.
- Playwright drives Chromium for scraping. The dev container provides a consistent development environment.
